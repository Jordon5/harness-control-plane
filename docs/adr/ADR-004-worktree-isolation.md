# ADR-004: 写入型任务强制 Git worktree 隔离

- 状态：Accepted
- 日期：2026-09-14

## 背景

多个 harness 并行工作时，若共享同一工作目录会出现：

- 文件互相覆盖
- git index 冲突
- 一个 agent 读到另一个的半成品
- 测试结果无法对应具体修改
- 失败后无法回滚

只读任务（分析、审查）不需要隔离；写入任务（实现）必须隔离。

## 决策

按 Stage 的 mode 决定隔离级别：

| Stage mode | 工作区 | 权限 |
|---|---|---|
| `read-only` | 主工作区 | 禁止写入 |
| `write` | 每个 Run 独立 Git worktree | 仅允许 `owned_paths` |
| `review` | 目标 run 的只读快照 | 只读 |

并发写入前的冲突检查：

```text
owned_paths 是否重叠
  ├── 不重叠 → 可并行
  └── 重叠   → 强制串行 或 触发 path-conflict 审批
```

合并只能经人工确认后由控制器执行（cherry-pick / apply patch）。

## 理由

- worktree 是 git 原生机制，隔离彻底且可回滚，无需自建沙箱
- `owned_paths` 把并发风险显式化，成为可校验声明而非约定
- 人工确认合并，避免自动合并带来不可逆后果

## 后果

- 磁盘占用随并发数增长，需要上限与清理策略
- worktree 创建/清理有开销，短任务可能不划算
- 需要处理主工作区未提交改动、worktree 残留等边界情况

## 替代方案

- **共享目录 + 锁**：粒度粗，agent 内部行为不可控，弃用
- **容器隔离**：隔离更强但成本高，超出 MVP 范围，后续可考虑
