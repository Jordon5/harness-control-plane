# ADR-008: 事件保留策略

- 状态：Accepted
- 日期：2026-09-14
- 更新：2026-09-15 决策为全量保留

## 背景

按 ADR-003，每条事件都保留 raw 原文。长时间运行多个 harness 会产生大量事件行，SQLite 文件可能快速膨胀。

需要在"可回放 / 可排障"与"存储可控"之间定策略。

## 候选方案

### A. 全量保留（选定）

优点：完整回放、排障无损失、实现最简单
缺点：文件持续增长，无上限

### B. 滚动清理（按时间或条数）

优点：存储有上限
缺点：旧运行不可回放；需要清理任务与策略配置

### C. 分层：摘要常驻 + 原文按需

- 事件表保留全部**归一化事件**（体积小）
- `raw` 原文单独归档（可按 run 落文件或定期清理）

优点：排障能力保留，主表可控
缺点：实现复杂，需管理两处存储

## 决策

采用**方案 A：全量保留**。

- 事件与其 `raw` 原文全部保留，首期不设清理
- 存储层预留 `raw` 的可分离存储位，便于后续平滑切换到方案 C

## 决策依据

- 事件流是 bad token 归因、用量分析等后续需求的**主数据底座**（见 development-plan §11 F2）——删减即损失不可回溯的分析能力
- MVP 阶段数据量小，全量保留排障价值高、实现最简单
- 方案 C 的复杂度在数据量真正成为问题前不值得承担

## 后果

- 需监控 `.hcp/hcp.db` 体积增长，设定观察阈值
- 未来切换 B/C 时，需新增清理 / 归档逻辑，但事件模型不变

## 替代方案

- **方案 B**：牺牲回放与后续分析能力，与 F2 需求冲突，弃用
- **方案 C**：能力最全但实现复杂，后置；保留其可迁移性
