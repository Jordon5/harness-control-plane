# ADR-010: 首期不支持跨仓库（多 Project）编排

- 状态：Accepted
- 日期：2026-09-15

## 背景

当前模型假设一个 Task 的 DAG 在**单个 git 仓库**内执行（`Task.project_id` 单值）。
存在跨仓库编排的潜在需求（如同时改前端与后端仓库），但会显著增加数据模型与合并逻辑的复杂度。

## 决策

首期（MVP）**不支持跨仓库编排**，但**不写死单仓库假设**，预留扩展空间：

- `Task` / `Run` 的数据模型不假设仓库唯一性（如 workspace 解析、路径处理走统一 Project 抽象，而非硬编码单个 repo 根）
- 跨仓库需求首期由"多个 Task 各自执行"承接
- 未来扩展为多 Project 时，应是**增量扩展而非重写**

## 理由

- 跨仓库编排的收益在 MVP 阶段不明确，而复杂度（多 worktree、多仓库合并、事务边界）很高
- 单仓库已足以验证 DAG 调度、隔离、路由、合并的核心假设
- 过早引入多 Project 会污染 M1 域模型

## 后果

- M1 必须审慎：任何"单仓库"假设需显式标记为临时约束，不得渗入接口签名
- 若未来确认需要，可能需要迁移 `project_id`（单值 → 多值 / 关联表）

## 替代方案

- **首期即支持多 Project**：复杂度前置，MVP 被拖慢，弃用
- **完全固定单仓库**：未来扩展需重写，违背可扩展性原则，弃用
