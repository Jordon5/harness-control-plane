# 开发规则

> 长期约定，每次开发都遵守。记录于 2026-09-15。

---

## R1 — 每阶段一个文档目录（留案）

每一步开发都在 `docs/` 下开一个**阶段目录**（`docs/M1/`、`docs/M2/` …），内含：

| 文件 | 内容 | 何时写 |
|---|---|---|
| `plan.md` | 目标、交付物、任务分解、**验收点** | 开工前 |
| `verification.md` | 对照验收点逐条核查的记录 + 证据 | 完工后 |

规范：

- **开工前**先写 `plan.md`，把"要做什么、验收点是什么"定清楚。
- **完工后**必须写 `verification.md`，**以 plan 的验收点为准逐条核查代码是否达到**，附证据（测试结果、命令输出、偏差说明）。
- **验收点未全部通过，不得进入下一阶段**；任何偏差必须显式记录（如环境限制导致改用替代方案）。

## R2 — 代码链路影响图 + 增量测试

维护 [`impact-graph.md`](./impact-graph.md)：记录模块/文件之间的依赖链路与测试覆盖映射。

规范：

- **每次改代码，先查影响图**，确定受影响的链路。
- **只测受影响链路的测试**，不跑全量——除非影响面不确定、改动跨多个模块，或改动落在公共契约（如 `@hcp/contracts`）。
- 新增 / 修改模块时，**同步更新影响图**。

命令（vitest）：

```bash
npx vitest run <受影响的测试文件…>     # 精确指定
npx vitest related <改动文件…>          # 按依赖自动选
```

> 判断依据：影响图给出"改哪个节点 → 影响哪些节点 → 对应哪些测试"的映射。契约节点影响面最大，改它时跑全量是合理的。

## R3 — 临时目录建在包外

临时目录 / 临时产物一律建在**包外**（仓库根 `.tmp/`，已 gitignore），**不得在 `packages/**` 内**创建 tmp。

目的：保持各包独立、干净，避免临时物污染包边界或被打包分发。

- 仓库级临时目录：`<repo>/.tmp/`
- 包内只放**确定性内容**：源码、测试、配置
- 测试若需落盘，用 `:memory:`、系统临时目录或 `<repo>/.tmp/`；**不落进包内**
