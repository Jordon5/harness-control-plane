04两条"管道" · 别混淆

"消息管道"在架构上是两件不同的事，分属不同里程碑。

① Run 事件流

单个 Run 的输出 → 归一化事件 · 已实现（M2）
harness 进程→ adapter parseLine→ UnifiedEvent→ Store.events

② 平台事件总线

多 Run 事件 → 多消费方订阅 · 未做（M5 / ADR-007）
多个 Run→ 事件总线→ CLI / TUI / WebUI / CI

05adapter 之间如何"通信"

核心架构分叉。平台的价值押在这里。

推荐 · 黑板
adapter A→ core（黑板：产物 / 事件 / 上下文）→ adapter B
避免 · 直连
adapter A⇢ adapter B（绕过内核） → 退化为电话线，失去隔离 / 可观测 / 可替换

结论："adapter 间通信协议"不是一条新协议，而是 D1 任务态注入 + D9 上下文工程 的落地 —— 由 core 中介的产物传递。
