# M3 必须冻结的契约

> **未写入 `@hcp/contracts`。** 不定这四块，调度器只能继续把上下文塞进 `prompt: string`，且会把 git / 某家 CLI 焊进内核。
> 原则：core 决定「注入什么 / 何时 / 在哪」；adapter 决定「怎么送」。

---

## A. `ContextPack`（core → adapter）

结构化「这一跳带什么」。**引用，不塞全文**（D9 存在的理由：只做状态注入 → prompt 臃肿）。

```typescript
interface ArtifactRef {
  stageId: string;
  runId: string;
  path: string;          // 产物路径，harness 自己去读
  kind: ArtifactKind;
}

/** 注入用的瘦上下文，不把 Store 的 ContextRecord 整行塞给 adapter。 */
interface ContextItem {
  kind: ContextKind;
  key: string;
  value: string;
}

interface ContextPack {
  goal: string | null;
  stageIntent: string;              // 本节点要做什么
  upstream: ArtifactRef[];          // 上游产物指针（含 stageId，按依赖解析）
  projectContext: ContextItem[];    // D9 精选后的项目级条目
  ownedPaths: string[];
  doneCriteria: string | null;
}
```

**`CreateRunArgs` 演进（已拍：并列，不替换）**：新增可选 `context?: ContextPack`，保留 `prompt`。无 `injection` 的旧 adapter 只读 `prompt`（由 core 把 `stageIntent` 填进去）。符合 [00-版本.md](./00-版本.md) 可选字段 = minor。

adapter **不得**要求 pack 里带上游全文。需要内容时用 `path` / `@file` / 工作区相对路径。`ownedPaths` 仍留在 `CreateRunArgs` 顶层（执行约束）；pack 内再带一份是给模型看的，允许重复。

### YAML 缺口（必须随 ContextPack 一起补，否则字段无源）

当前 `StageDefinition` **没有** `intent` / `doneCriteria`。不补的话 `stageIntent` 只能拼 `task.goal + stage.id`，完成判据只能猜 `output`。

```yaml
# schema: 1 增量（可选字段，旧 YAML 仍合法）
stages:
  - id: implement
    intent: 按 analysis.md 实现认证模块
    done: tests/auth 通过且 owned_paths 内有改动
```

对应 TS（均 `string | null`，默认 `null`）。`output` 仍是产物路径，与 `done` 不是一回事。

**已拍（schema:1 可选增量）**：`intent` / `done` 进入 YAML 与 `StageDefinition`。缺省 `null` 时 `stageIntent` 回退 `task.goal ?? stage.id`，`doneCriteria` 为 `null`。旧 YAML 仍合法。

## B. 注入通道声明（adapter → core）

挂在 `HarnessManifest`，**optional**（00-版本 §5）。core 按声明组装，不硬编码 `pi`/`claude` 的 flag。

```typescript
type InjectionChannel =
  | 'argv-prompt'              // 位置参数 / 主消息
  | 'system-prompt'            // --system-prompt 类替换
  | 'append-system-prompt'     // --append-system-prompt，可多次、可文件
  | 'file-refs'                // @files / 等价引用
  | 'context-files'            // AGENTS.md / CLAUDE.md 发现
  | 'stdin'
  | 'json-body'                // HTTP adapter
  | 'env';

interface InjectionProfile {
  channels: InjectionChannel[];
  /** 上下文文件是否由 harness 自己发现；true 时 core 可用 --no-context-files 关掉以免双份。 */
  discoversContextFiles?: boolean;
}

interface HarnessManifest {
  // …现有字段
  injection?: InjectionProfile;
}
```

**组装权在 adapter，不在 core。** `injection` 只声明「有哪些通道」，不声明「pack 哪一字段走哪条通道」。core 交出 `ContextPack`，adapter 的 `buildArgs` / HTTP body 自己翻译（例：pi 把 `upstream` → `@path`，`projectContext` → `--append-system-prompt`）。core **不**按通道拼 CLI。

**降级（旧 adapter 无 `injection`）**：core 把 `stageIntent` 写入 `prompt`，不拒绝写入型 Stage（否则 M2 的 pi 在声明补上之前无法被调度）。

## C. `Scheduler`

规划（requirements D1）：藏在接口后，可换 Temporal。M3 至少冻边界，不要写死一个无法替换的循环。

```typescript
interface SchedulerDeps {
  store: Store;
  workspace: Workspace;
  /** 按 harnessId 解析 adapter；Scheduler 不 new 具体类。 */
  resolveAdapter(harnessId: string): HarnessAdapter;
  /** kind=local-command 等非 harness 节点；缺省则该类 Stage 直接 failed。 */
  resolveExecutor?(kind: StageKind): StageExecutor;
  now?: () => Date;
}

interface Scheduler {
  /** 依赖在构造时注入，不在每次 submit 传入。 */
  // constructor(deps: SchedulerDeps)
  submit(task: TaskDefinition): Promise<{ taskId: string }>;
  interrupt(taskId: string): Promise<void>;
}
```

- **拥有**：就绪队列、状态推进、失败传播、超时/重试、组装 `ContextPack`、写 Store（含四根桩：event / usage / configRef / context）。
- **不拥有**：具体 adapter、git 细节、路由策略（M3 可取 `preferred[0]`，接口仍走 `resolveAdapter`）、对外查询（status/logs **读 Store**，Scheduler 不另开查询 API）。
- **失败语义**：依赖失败 → 下游保持 `pending`、不再入就绪队列（**不**新增 `blocked` 状态，以免改 `TaskStatus` 枚举）。retry 耗尽 → `failed`。
- **`configRef`（已拍）**：非空字符串，一次 Run 内不变。算法 = **ContextPack 的稳定哈希**（字段排序后 JSON + 固定 hash；实现时定具体函数，契约不绑算法名）。无 pack 时用 `prompt` 字符串的同样哈希。

## D. `Workspace`

与 Scheduler 分离，避免调度循环 import git。

```typescript
interface Workspace {
  /** 写入型：创建或复用 worktree，返回绝对路径。 */
  acquireWrite(project: ProjectRecord, taskId: string, stageId: string): Promise<string>;
  /** 只读型：该 Project 的主工作区；实现须保证无写权限或约定不写。 */
  acquireRead(project: ProjectRecord): Promise<string>;
  release(stageId: string): Promise<void>;
}

/** glob 重叠检测：纯函数，不挂在 Workspace 实例上（与是否 git 无关）。 */
function ownedPathsOverlap(a: string[], b: string[]): boolean;
```

`ProjectRecord` 入参避免把「单仓库」焊进签名（ADR-010）。路径归一化、Windows 盘符、worktree 根（`.hcp/worktrees`）是实现细节。

重叠时：M3 MVP 可强制串行；`path-conflict` Gate 是 M4。调度循环调用 `ownedPathsOverlap`，不调用 git。

## E. 可选：`StageExecutor`（local-command）

`StageDefinition.kind` 已有 `local-command`。不要塞进 `HarnessAdapter`。

```typescript
interface StageExecutor {
  kind: StageKind;
  run(stage: StageDefinition, ctx: { workspace: string; timeoutMs: number | null }): Promise<UnifiedResult>;
}
```

**已拍：M3 实现内置 `local-command` executor**（否则示例 DAG 的 verify 节点无法跑）。Scheduler 只通过 `resolveExecutor`，不 `if (kind === …)`。

## 与黑板模型的关系

```
run A 产物 → Store（黑板）
  → 组装 Stage B 的 ContextPack（引用 A + **该 project 全部 ContextRecord**）
  → adapter B 按 manifest.injection 翻译通道
  → B 启动
```

无 adapter↔adapter 直连。本文件四块就是「adapter 间通信」的全部契约面。

### D9 精选规则（已拍：M3 全量）

M3 **注入该 project 的全部 `ContextRecord`**，不新增 `context_keys`。量小；过滤字段晚加不还债（pack 仍是 `ContextItem[]`）。
